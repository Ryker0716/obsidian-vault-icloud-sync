# Vault iCloud Sync

[中文](README.md) | [English](README.en.md)

一个 Obsidian 桌面插件：把**本地 vault** 单向同步到 **iCloud 备份目录**，并在需要时提供**逐文件可控的反向操作**——按备份恢复、清理备份冗余、差异清单里逐项选「备份」还是「还原」。

> [!note] 为什么会有这个插件
> 把 vault 放进 iCloud Drive 直接用，会踩到「多设备同时改、文件互相覆盖、`.icloud` 占位文件读不到」这些坑；而 Obsidian Sync 是付费闭源服务，Remotely Save 之类的插件又很难让你精确控制**哪些文件**要回滚。
> 这个插件的思路是：**本地 vault 是唯一真源，iCloud 那份只当备份**。日常只有一条单向同步，永不删除；要回滚时再显式地、逐文件地决定方向。

## 功能

| 能力 | 说明 |
|------|------|
| **每日自动同步** | 每天首次启动 Obsidian，等工作区就绪后延迟 N 秒（默认 60）扫一遍，有新增/更新才同步 |
| **手动同步** | 命令面板 / 侧边栏图标 / 设置页「立即同步」 |
| **仅检查差异（推荐入口）** | 只读扫描后弹**差异清单**：每行标明「本地独有 / 两边不同 / 备份独有」，勾选后逐项选方向（备份 或 还原）再执行 |
| **按备份恢复本仓库** | 列出所有可恢复文件，勾选哪些就恢复哪些；默认不删本地独有文件 |
| **清理备份冗余** | 列出「备份有、本地已没有」的文件，勾选哪些就搬进备份的回收目录 |
| **上次结果** | 弹窗展示上次同步 / 差异处理 / 恢复 / 清理的条数、耗时与清单样例 |
| **回收目录** | 所有被移走的文件都进 `.vault-sync-trash/<时间戳>/`，不做真正删除 |

差异清单里每一行长这样：

```
☐ 两边不同  [备份]  03-Personal/2.公司组织/某某公司.md     ← 点行内按钮可切成「还原」
☐ 备份独有  [还原]  02-Business/1.会议/2026-10-20-某会议.md
☐ 本地独有  [备份]  05-Resources/2.技术文章/某文章.md
☐ 类型冲突  [备份]  04-Operations/某文件夹         ← 同一路径一边是文件一边是目录，目标侧整路径先进回收
```

- 批量按钮：`全不选` / `全选` / `全部备份` / `全部还原`，作用于**当前筛选结果**；
- 路径筛选框边输边过滤，勾选状态不会因筛选丢失；
- 列表分块渲染（一次 300 行 + 「再显示 300 条」），上千条差异也不会卡；
- 复制时会把**源侧的修改时间**一并写过去，所以处理完的下一轮同步不会又把它当成差异。
- **空目录差异不进清单**（清单只列文件）：只有空目录差异时会直接提示数量，「立即同步」会把本地独有的空目录补到备份，「清理备份冗余」会移除备份侧的冗余空目录。
- **类型冲突**（同一路径一边文件一边是目录）：可备份或还原，执行时先把目标侧整路径搬进回收，再复制源侧整个目录；「立即同步」也会先把冲突路径的备份侧搬进回收再传输，避免 rsync 报错或覆盖不进回收；
- **执行前重验**：写每个文件前重新核对目标侧，扫描后被改动的条目自动跳过并列出，不覆盖新改动；
- 「按备份恢复」的清单同样分块渲染（一次 300 行）。

## 安装

### 手动安装（推荐）

1. 下载本仓库（`git clone` 或 Download ZIP）；
2. 把 `main.js`、`manifest.json`、`styles.css` 放进 `<你的 vault>/.obsidian/plugins/vault-icloud-sync/`；
3. Obsidian → 设置 → 第三方插件 → 关闭「安全模式」→ 刷新 → 启用 **Vault iCloud Sync**。

> [!warning] 仅桌面端
> 插件依赖 Node 的 `child_process` / `fs` 和系统 `rsync`，移动端无法运行（`isDesktopOnly: true`）。

## 快速开始

1. 打开插件设置，填 **iCloud 备份目录（同步目标）**，例如
   `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/我的仓库备份`
   （必须是一个**已存在**、且**不等于**当前 vault 的目录）；
2. 先点 **仅检查差异**，看看清单是否符合预期；
3. 没问题就用 **立即同步** 或等每日自动同步；
4. 需要回滚时，按备份恢复本仓库 / 清理备份冗余 / 差异清单，按需勾选执行。

设置项一览：

| 设置 | 默认 | 说明 |
|------|------|------|
| 启用每日自动同步 | 开 | 每天首次启动跑一次，日期记在 `data.json` 的 `lastAutoDate` |
| 启动后延迟（秒） | 60 | 等 Obsidian 索引和其它插件加载完 |
| iCloud 备份目录 | 空 | 必填，本地不存在时报错 |
| 本地 vault 根目录 | 空 | 留空 = 当前打开的 vault |
| 按文件内容比对（MD5） | 关 | 默认按「大小 + 修改时间（秒）」比对，和 rsync 一致；开启后按内容比对，大仓库明显变慢 |
| 镜像删除 iCloud 多余文件 | 关 | 开启后同步时会把备份里本地已不存在的文件移入回收目录 |
| 有变更时提示 / 无变更时也提示 | 开 / 关 | Notice 开关 |
| 超时（秒） | 1800 | 单次 rsync 上限 |
| 排除规则 | 见下 | 每行一条：前导 `/` 锚定根目录；含 `/` 不带前导的按路径尾部匹配任意层级（与 rsync 同语义）；不含 `/` 的按文件名匹配任意层级 |

默认排除：

```
/.trash        /.claudian     /.omo              /.vault-sync-trash
/.agents       /.claudeignore /.opencode         .DS_Store
/.claude       /.copilot      /.opencodeignore
/.gitignore    /.obsidian
```

`.obsidian` 被排除意味着**插件配置、主题、片段、快捷键不进备份**——恢复出来的 vault 是「只有笔记」的干净副本，请不要把备份那份直接当工作 vault 用。

## 安全设计

反向操作会改写文件，所以每一步都设了闸：

| 场景 | 保护 |
|------|------|
| 所有反向操作 | 先弹确认框，默认**全不选**，勾选并确认后才写盘；点取消 / Esc 一个字节都不动 |
| 路径校验 | 当前打开的 vault 必须就是配置的本地目录，否则直接中止（不做「善意继续」） |
| 恢复 | 备份里扫不到任何文件 → 中止；备份文件数不到本地一半 → 警告；有文件本地更新 → 警告「该用同步而不是恢复」 |
| 清理 | 本地扫不到任何文件 → 中止（防止挂错盘 / iCloud 未就绪时把整份备份搬走） |
| 删除 | 一律 `rename` 进 `.vault-sync-trash/<时间戳>/`，同卷瞬间完成，可随时找回；失败退化为「复制 + 删除」 |
| 镜像删除同步 | 本地扫不到任何文件时直接中止（与「清理」同一守卫），防止本地目录配置错误把整份备份搬空 |
| iCloud 占位 | `.xxx.icloud` 对 rsync 一律 `--exclude`，镜像删除的 `--delete` 碰不到它们；恢复时其本地同名文件不计入「本地独有」，不会被误搬进回收 |
| 符号链接 | 逐文件复制前检查目标，目标是链接先摘掉再写，不会穿透覆写链接指向的外部文件 |
| 执行前重验 | 差异处理 / 恢复写每个文件前重新核对目标侧状态，扫描后被改动的条目自动跳过 |
| 占位残留 | 同步后备份侧「真身已存在」的 .xxx.icloud 占位移入回收，不再与真身并存 |
| 镜像删除对称豁免 | 本地被 iCloud 驱逐成占位的文件，其备份真身不算冗余、也不会被 --delete 碰（逐个 --exclude 保护）；备份未下载的占位，其本地同名活文件不算「本地独有」 |
| 搬迁失败兜底 | 移入回收失败的文件自动加进 rsync 排除清单，--delete 够不到它们，留待下一轮重试 |
| 批量按钮随筛选 | 恢复 / 清理弹框的「全选 / 反选」只作用于当前筛选结果 |
| 目录校验 | 备份目录 / 本地根目录必须是文件夹，填成文件时所有入口直接拒绝 |
| 多任务 | 同一时刻只允许一个同步 / 恢复 / 清理任务，重复触发直接提示 |

## 两个 macOS 专有坑（已在实现中规避）

写在这里免得以后有人「顺手优化」回去：

1. **不能用 `rsync -i` 的输出判断差异。** macOS 自带的 `/usr/bin/rsync` 其实是 openrsync，它把非 ASCII 文件名转义成 `\#ooo`：「战略规划.md」变成 `\#210\#230\#225` 之类，中文名全对不上。所以差异判断由插件自己 `readdir` 扫描目录树完成。
2. **不能用 rsync 的 `--backup-dir` 做回收站。** openrsync 在 `--delete` 与 `--backup-dir` 同时使用时会**静默跳过删除**。所以回收动作由插件自己用 `fs.rename` 完成。

另外，iCloud 未下载的文件在磁盘上表现为 `.foo.md.icloud` 占位，扫描与恢复都会把它们剔除，避免把占位文件当正文复制；rsync 参数也带 `--exclude=*.icloud`，所以镜像删除的 `--delete` 同样碰不到它们。

## 测试

零依赖，不需要构建，Obsidian API 用桩替代，跑真实文件系统 + 真实 rsync：

```bash
node tests/run.js
```

覆盖 45 个场景：目录树比对、正向同步、恢复（默认/勾选/零勾选/取消/空备份）、清理（部分勾选/本地为空/无冗余）、差异处理（默认方向/指定方向/处理后再扫/零勾选）、设置页与命令注册；1.2.1 / 1.3.0 起另有镜像删除、符号链接、iCloud 占位、类型冲突、中缀排除规则、执行前重验、任务锁、分块渲染、目录校验等 19 个回归场景（每个都先在旧代码上验证会失败）。

## 限制

- **不是双向同步**：不做冲突合并，也不监听文件变化实时同步，只在启动时和手动触发时跑；
- **不做版本历史**：想要历史版本请另配 Git 或 Time Machine；
- 备份那份 vault **不要直接编辑**：下一次同步会用本地版本覆盖它（要用手机看笔记请另配只读方案）；
- 依赖系统 `rsync`（macOS 自带 openrsync 即可），路径可在设置里改。
